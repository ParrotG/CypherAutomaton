# IN-CYPHER 工程说明

本文档描述当前代码在 `master` / 当前开发分支上的实际结构与行为，面向后续接手者。旧版 bridge/session 设计已不再代表当前实现。

## 1. 项目目标

项目为 IN-CYPHER Hackathon 提供一套自主解题基础设施：

- `incypher_bridge`：连接 raw TCP + PoW 题目的中间层，也可作为管理多条独立 upstream connector 的多 Agent 服务。
- `incypher_agent`：最小化 model-tool loop，默认使用 DeepSeek-compatible API。
- `incypher_scheduler`：任务级、task-blind 调度器，创建 bridge connector 和 worker 进程，并维护 worker 上限与补位。
- Blackboard：任务级共享记录板，供并发 worker 和后续 worker 拉取已完成工作摘要。

当前支持的题目输入方式：

1. raw TCP：`HOST:PORT` 或 `nc HOST PORT`，由 bridge 完成 PoW。
2. HTTP(S) URL：worker 直接访问 URL，不走 bridge，不需要 PoW。
3. 本地文件/目录：worker 获得只读副本，不走 bridge，不需要 PoW。

## 2. 总览

```text
incypher_scheduler
  ├── 解析 --target
  ├── raw TCP -> 启动 embedded bridge -> connector -> worker 本地 endpoint
  ├── URL    -> worker 直接访问 URL
  ├── files  -> 复制到每个 worker workspace/challenge_files
  ├── 维护 max-concurrent-workers / max-total-workers
  ├── 每个 scheduler run 使用独立 attempt 目录
  └── worker 退出时写系统 blackboard 记录

incypher_agent
  ├── model-tool loop
  ├── bash / str_replace_editor / report_flag
  ├── bwrap sandbox
  ├── 预装通用 Python 工具环境
  └── task blackboard: /blackboard

incypher_bridge
  ├── FastAPI HTTP 控制面
  ├── asyncio connector/upstream generation
  ├── HTTP API 客户端 BridgeClient
  └── raw TCP PoW
```

## 3. Bridge v2

### 3.1 模块

```text
src/incypher_bridge/
├── app.py          # FastAPI 控制面
├── cli.py          # serve 入口
├── connector.py    # connector / upstream generation
├── manager.py      # connector registry
├── models.py       # HTTP API 模型
├── client.py       # httpx BridgeClient + local socket helper
├── settings.py     # bridge 运行配置/team key
├── store.py        # connector 元数据、事件、raw stream
├── pow.py          # PoW 求解
├── config.py       # 旧工具：.env.local / team key 读取
├── paths.py        # 旧工具：run 目录路径
├── transcript.py   # 旧工具：JSON/字节预览
└── duration.py     # 时长解析
```

`connector.py` 是对外核心：

- 一个 connector 是一个稳定本地 TCP endpoint；
- 底层可经历多个 upstream generation；
- upstream 断开时，本地 agent 会看到 EOF，但 connector endpoint 不消失；
- `auto_reconnect=true` 时自动重新连接并重新做 PoW。

### 3.2 HTTP API

启动：

```bash
uv run python -m incypher_bridge serve \
  --api-host 127.0.0.1 \
  --api-port 8765 \
  --state-dir .cypher_bridge/bridge \
  --env-file .env.local \
  --max-handshakes 4
```

接口：

| Method | Path | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| POST | `/connectors` | 创建 connector |
| GET | `/connectors` | 列出 connector |
| GET | `/connectors/{id}` | 查询 connector |
| GET | `/connectors/{id}/events` | 读取事件 |
| POST | `/connectors/{id}/reconnect` | 强制新 upstream generation |
| DELETE | `/connectors/{id}` | 停止并删除 connector |

创建 connector：

```bash
curl -X POST http://127.0.0.1:8765/connectors \
  -H 'Content-Type: application/json' \
  -d '{
    "connector_id": "worker-a",
    "target": "47.236.162.54:30068",
    "auto_reconnect": true
  }'
```

响应中 `endpoint` 是 worker 要连接的本地 TCP 地址。

### 3.3 Connector 生命周期

状态：

```text
connecting -> ready -> reconnecting -> ready -> ...
                         \-> upstream_closed / closed
```

关键行为：

- 一个 connector 同时只允许一个本地 Agent 连接；
- Agent 断开后 upstream 保留；
- 无 Agent 时 upstream 数据进入 bounded pending buffer；
- upstream 断开时关闭本地 Agent、清空当前 generation pending buffer、generation 递增；
- 自动重连时 endpoint 保持不变；
- worker 应把 EOF 当作“当前协议会话结束”，重新连接同一个 endpoint。

### 3.4 PoW

真实 PoW 关系：

```python
mac = hmac.new(team_key, nonce.encode("ascii"), sha256).digest()
sha256(mac + str(counter).encode("ascii")).digest()
```

其中 `counter` 以 ASCII decimal 加换行发送。

当前只保留这一种真实算法，不再包含旧版多 variant 猜测。

## 4. Agent

### 4.1 模块

```text
src/incypher_agent/
├── cli.py          # run / doctor / smoke / show / sandbox-init
├── config.py       # 配置解析
├── loop.py         # model-tool 主循环、上下文预算
├── model.py        # OpenAI-compatible client
├── prompt.py       # system / initial user message
├── state.py        # state.json / events.jsonl / artifacts
├── tools.py        # bash / str_replace_editor / report_flag
├── sandbox.py      # local / bwrap sandbox
├── toolchain.py    # 通用 Python 工具环境
└── blackboard_cli.py  # bb-write / bb-read
```

### 4.2 Sandbox

默认 `sandbox_backend=bwrap`。

每次 bash 调用在独立 namespace 中运行：

- `--unshare-pid`
- `--unshare-uts`
- `--unshare-ipc`
- 私有 `/tmp`
- 只读写挂载 workspace 到 `/workspace`
- 项目根目录、`.env.local`、其他 worker workspace 不可见
- shared blackboard 挂载到 `/blackboard`
- 只读挂载系统基础目录
- API key 在宿主机 AgentLoop 中，bash 在独立 PID namespace，不能读取宿主 AgentLoop 的 `/proc/<pid>/environ`

### 4.3 通用 Python 工具环境

`toolchain.py` 会创建共享只读 venv：

```text
.cypher_bridge/agent-tools/
```

预装：

```text
pwntools
requests
pycryptodome
z3-solver
pyelftools
virtualenv
```

初始化：

```bash
uv run python -m incypher_agent sandbox-init
```

Agent 可以在 workspace 创建自己的 venv：

```bash
python -m virtualenv .venv
.venv/bin/pip install <package>
```

### 4.4 工具

- `bash`：在 sandbox 内执行；有 timeout、输出截断、完整输出落 artifacts。
- `str_replace_editor`：view / create / str_replace / insert，限制在 workspace 内。
- `report_flag`：接受 raw body、`flag{...}`、`INCYPHER{...}` 等输入，程序统一归一化为 `INCYPHER{body}`；写 `candidate.json` 并进入人工验证等待，不再立即结束 run。

### 4.5 上下文预算

移除 `max_model_calls` / `max_tool_calls`。只保留：

- `max_seconds` 墙钟时限；
- `context_window_tokens` 默认 `1_000_000`；
- `context_reserve_tokens` 默认 `8_000`。

每次模型调用前估算下一次 prompt token 总量，达到：

```text
context_window_tokens - context_reserve_tokens
```

时停止，写 `escalation.json`，退出码 `10`。

### 4.6 模型重试与人工验证

`ModelClient` 对以下 error 使用指数退避 + 随机抖动：

- 网络连接错误；
- timeout；
- rate limit；
- provider 5xx。

`AgentLoop` 会把 `max_seconds` 作为 monotonic deadline 传给模型客户端；临时 API 不可用时，worker 保持存活并持续重试，而不是立即 `MODEL_ERROR` 退出。

`report_flag` 流程：

```text
candidate reported
  -> candidate.json
  -> state = WAITING_VERIFICATION
  -> 等待 verification.json
      success: 写 flag.json，退出 0
      failed: 把 feedback 注入原 messages，继续同一 model-tool loop
```

人工验证命令：

```bash
uv run python -m incypher_scheduler candidates --task-id <task_id>
uv run python -m incypher_scheduler review \
  --task-id <task_id> --run-id w0001 \
  --result failed \
  --feedback "INCYPHER{f989c670} rejected; try the central directory CRC" \
  --state-dir .cypher_bridge/scheduler
```

不传 `--attempt-id` 时，`review` 会自动选择包含该 `run_id` 的最新 attempt；如需精确指定可以显式传入 `--attempt-id`。

如果希望恢复旧的一报即退行为，可在 `run` 时传 `--no-wait-verification`；worker 会立即写 `flag.json` 并退出 0，不再等待人工 `review`。

## 5. Scheduler

模块：

```text
src/incypher_scheduler/
├── __init__.py
├── __main__.py
├── cli.py
├── config.py
├── scheduler.py
└── targets.py  # classify raw TCP / URL / files
```

### 5.1 Target 类型

`--target` 支持：

1. raw TCP：

   ```text
   HOST:PORT
   nc HOST PORT
   ```

   Scheduler 启动 embedded bridge，为每个 worker 创建 connector，完成 PoW。

2. URL：

   ```text
   http://...
   https://...
   ```

   不启动 bridge，worker 直接访问 URL。

3. 文件/目录：

   ```text
   /path/to/challenge-files
   /path/to/single-file.bin
   ```

   不启动 bridge，Scheduler 将文件复制到每个 worker：

   ```text
   workers/<worker_id>/agent/workspace/challenge_files/
   ```

   Agent prompt 中的 target 是：

   ```text
   /workspace/challenge_files
   ```

### 5.2 Attempts 与 Worker

每次 scheduler 运行创建一个 attempt：

```text
tasks/<task_id>/attempts/<attempt_id>/workers/
```

因此同一个 `task_id` 多次运行不会覆盖旧 worker 目录、旧 events、旧 flag 或旧 workspace。

worker 上限：

- `--max-concurrent-workers`：同时运行 worker 上限；
- `--max-total-workers`：总 worker 上限。

worker 退出后：

- 如果 exit code 0，视为成功，停止调度并清理其他 worker；
- 如果非 0，视为结束，在总上限内创建补位 worker；
- 不进行语义错误检测、偏移检测或工作认领。

### 5.3 Worker 命令

默认：

```text
python -m incypher_agent run
```

Scheduler 追加：

```text
--run-dir <attempt>/workers/wNNNN
--challenge-id <task_id>
--run-id wNNNN
--agent-endpoint <endpoint>   # 仅 raw TCP
--env-file ...
--max-seconds ...
--context-window-tokens ...
--context-reserve-tokens ...
--bash-timeout ...
--max-tool-output ...
--sandbox-backend ...
--sandbox-tool-root ...
--blackboard-dir ...
--blackboard-path ...
--target ...
```

也可通过：

```bash
--worker-command-json '["python", "/path/to/worker.py"]'
```

替换 worker 命令前缀。

## 6. Blackboard

### 6.1 目录

Task 级目录：

```text
.cypher_bridge/scheduler/tasks/<task_id>/blackboard/
└── records/
```

每个 worker 的 sandbox 中挂载：

```text
/blackboard
```

### 6.2 记录语义

Prompt 规则：

```text
After a meaningful unit of work concludes, briefly record any outcome
that may be useful to other agents. Do not log routine intermediate steps.
```

记录自由格式，系统不解析、不规定 schema、不做语义总结、不阻止多个 worker 同时探索。

### 6.3 原子写入

Sandbox 内提供：

- `bb-write`：从 stdin 读入自由内容，写入唯一记录文件；
- `bb-read`：按文件名顺序输出已有记录。

`bb-write` 使用：

```text
临时文件 -> fsync -> os.replace 原子 rename
```

避免多 writer 覆盖和半写文件。

### 6.4 系统记录

worker 正常或异常退出时，Scheduler 写极小系统记录：

```json
{
  "attempt_id": "attempt-...",
  "worker_id": "w0001",
  "exit_code": 0,
  "started_at": "...",
  "finished_at": "...",
  "run_dir": "..."
}
```

Scheduler 不记录语义 summary。

## 10. 安全要点

- `.env.local` 必须 `0600`。
- `DEEPSEEK_API_KEY` 只从 `.env.local` 读取。
- bwrap sandbox 内不挂载项目根目录和 `.env.local`。
- 共享 blackboard 只包含任务级记录，不要写 team key、API key 等秘密。
- bridge HTTP API 默认只绑定 `127.0.0.1`。
- bwrap 默认共享网络 namespace，因此 sandbox 仍可能访问网络；更严格模式可后续引入 bridge Unix socket + `--unshare-net`。

## 11. 已知限制 / TODO

1. 官方 ADK/solver 未发布，PoW 已按现场行为实现为唯一算法。
2. bwrap 是 per-bash-call 沙箱，后台任务不能跨多次 tool call 存活。
3. 暂未实现 Docker/Podman sandbox backend。
4. Blackboard 不做解析、语义去重、任务认领或 push 通知。
5. Scheduler 不做语义错误检测、偏移检测或自动重试策略分类；flag 验证目前依赖人工 CLI。
6. URL 题依赖 sandbox 网络，未内置浏览器/HTTP 专用工具。
7. bridge HTTP 控制面与 sandbox 共享 localhost 网络时，Agent 可能扫描到控制端口。
8. 旧版 run/session/control socket 设计及旧日志不再兼容。
