## 1. 项目目标

按照官方 `CONTRACT.md`，提交一个可被 Arena 自动运行的 Docker 镜像：

- 使用官方 CTF Agent API 获取题单；
- 加载题目描述和附件；
- 自主解题；
- 调用官方提交接口上报 flag；
- 结果写入 `/work/results.json`；
- 运行环境为官方 sandbox：2 CPU / 2 GB / 256 PIDs，根文件系统 read-only，仅 `/work`、`/tmp` 可写。

当前主入口：

```text
arena/main.py
```

当前 Docker 入口：

```text
ENTRYPOINT ["python", "-m", "arena.main"]
```

### 4.1 `platform.py`

封装官方 API：

- `connect_from_env()`：读取 `CTF_BASE` / `CTFD_URL`、`CTF_TOKEN` / `CTFD_TOKEN`；
- `mode_from_env()`：`ARENA_MODE=auto|practice|competition`，默认 `auto`；
- `resolve_mode()`：`auto` 时若存在非 Practice 题则选 competition，否则选 practice；
- `select_targets()`：过滤 / 排序；
- `RetryingCTFdClient`：对平台瞬时错误做退避重试；
- 调用官方 `CTFdClient`。

### 4.2 `brain.py`

实现官方接口：

```python
Brain(run_bash, submit_flag, max_steps=40)
```

内部使用 `arena.runtime.loop.AgentRuntime`，并通过 `ModelClient.from_env()` 读取模型配置。

### 4.3 `runtime/model.py`

OpenAI-compatible 客户端：

- 读取显式 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`；
- 否则按 `LLM_PROVIDER` 选择：
  - `deepseek`：`DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`
  - `openrouter`：`OPENROUTER_API_KEY` / `OPENROUTER_BASE_URL` / `OPENROUTER_MODEL`
- OpenRouter 路径自动添加 reasoning/provider 路由；
- 支持网络错误退避重试。

### 4.4 `runtime/loop.py`

model-tool loop：

- 每次模型调用前估算 prompt tokens；
- 超过 `CONTEXT_WINDOW_TOKENS - CONTEXT_RESERVE_TOKENS` 返回 `context_limit`；
- `MAX_STEPS` 保留为不可达保险丝；实际由 `MAX_ATTEMPT_TOKENS` 与 context limit 控制；
- `MAX_PLAIN_REPLIES`：连续无 tool call 时停止，避免空转；
- 工具调用结果写回 messages；
- 支持 `run_bash`、`submit_flag`、`str_replace_editor`。

### 4.5 `runtime/events.py`

JSONL 事件日志：

- `run_start`
- `model_request`
- `model_reply`
- `tool_call`
- `tool_result`
- `assistant_plain`
- `context_limit`
- `model_error`
- `run_end`

注意：

- `model_request` 不再记录完整 `messages` 历史；
- 只记录 `message_count`、`last_message` 预览和 token 估算；
- 避免日志平方级增长。

### 4.6 `runtime/summary.py`

attempt 结束后生成 deterministic summary：

- 最近工具调用；
- 最近 tool result；
- workdir 文件；
- 结果状态和 context_limit 信息；
- 写入 `/work/<id>/attempts/NNN/summary.json`；
- 下一次 attempt prompt 会带上 `Previous attempt summary`。

### 4.7 `solver.py`

单题编排：

1. 准备附件（静态题可由 scheduler 预下载）；
2. dynamic_iac 调 `boot`；
3. 构建 prompt；
4. 设置 `run_bash` cwd 为 `/work/<id>`；
5. 调用 Brain；
6. 如果失败且还有 attempt，生成 summary 后重试；
7. `finally` 调 `destroy`；
8. 返回 result，含 `started_at` / `finished_at` / `seconds` / `submit_flags`。

### 4.8 `main.py`

全局调度器：

- `client.list_challenges()` 获取 brief；
- 对每个 brief 调 `client.challenge(id)` 获取完整题面；
- 按 points 升序；
- 静态题先预下载；
- 调度策略：
  - 如果有动态题，保持 1 个动态 task 在跑；
  - 剩余 slots 全部给静态题；
  - 动态题内部仍全局最多 1 个；
- 每个 task 完成后原子更新 `/work/results.json`；
- `timings` 包含每题 `started_at` / `finished_at` / `seconds`。

## 5. 官方平台 API

Base path：

```text
/api/agent/v1
```

认证：

```http
Authorization: Token <CTF_TOKEN>
User-Agent: Mozilla/...
Content-Type: application/json
```

接口：

| Method | Path | 说明 |
|---|---|---|
| GET | `/me` | team_id / team_key / solved |
| GET | `/challenges` | 题单 brief |
| GET | `/challenges/{id}` | 题面、文件、类型 |
| POST | `/challenges/{id}/instance` | boot dynamic instance |
| GET | `/challenges/{id}/instance` | instance 状态 |
| POST | `/challenges/{id}/instance/renew` | 续期 |
| DELETE | `/challenges/{id}/instance` | destroy |
| POST | `/challenges/{id}/submit` | 提交 flag |

PoW 使用：

```python
from ctfd import connect_pwn
sock = connect_pwn(host, port, team_key)
```

## 6. 运行时环境变量

| 变量 | 说明 |
|---|---|
| `ARENA_MODE` | `auto` / `practice` / `competition`，默认 `auto` |
| `INCLUDE_SOLVED` | practice 测试是否需要已解 |
| `ONLY_IDS` | 逗号分隔题号 |
| `CATEGORIES` | 逗号分隔 category |
| `SUBMIT_FLAGS` | `1` 真实提交，`0` 拦截并模拟成功 |
| `MAX_STEPS` | 最大模型调用轮数 |
| `MAX_ATTEMPTS` | 单题最大 attempt 数 |
| `CONTEXT_WINDOW_TOKENS` | 上下文预算 |
| `CONTEXT_RESERVE_TOKENS` | 上下文保留 |
| `MAX_ATTEMPT_TOKENS` | 单 attempt 累计 token 预算，默认等于 context window |
| `MAX_PLAIN_REPLIES` | 连续无 tool call 的停止阈值，默认 3 |
| `RENEW_INTERVAL_SECONDS` | 动态实例后台续期间隔，默认 60s |
| `MAX_CONCURRENT_CHALLENGES` | 总 challenge 并发 |
| `PRELOAD_WORKERS` | 静态题预加载并发 |
| `WORK_ROOT` | 默认 `/work` |
| `RESULTS_PATH` | 默认 `/work/results.json` |
| `CTF_BASE` / `CTFD_URL` | 官方平台地址 |
| `CTF_TOKEN` / `CTFD_TOKEN` | 官方 token |
| `LLM_PROVIDER` | `deepseek` / `openrouter` |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | Day 2 官方运行时注入；Day 1 通过镜像构建参数内置；运行时值优先级最高 |
| `DEEPSEEK_*` | 本地 DeepSeek 直连 |
| `OPENROUTER_*` | 本地 OpenRouter |

## 7. Bash 策略

`solver.make_run_bash` 在启动 shell 前做启发式检查，当前阻止：

- `find /`
- `find /proc|sys|opt|dev`
- `find /work`
- `grep -r ... /`
- `grep -r ... /work`
- `rg ... /`
- `cd /`
- 命令中引用 `events.jsonl` / `summary.json`

返回值：

```text
(blocked by arena bash policy: ...)
```

限制：

- 这只是命令字符串级策略，不是完整 OS 沙箱；
- 根文件系统 read-only 已限制写范围；
- agent 仍可能读取容器内其他普通文件，若需要可进一步收紧。

## 9. Docker

Dockerfile：

```dockerfile
FROM registry.in-cypher.com:5001/base/agent-base:latest
ARG DAY1_LLM_API_KEY=
ARG DAY1_LLM_BASE_URL=
ARG DAY1_LLM_MODEL=
ENV PYTHONPATH=/opt/agent \
    LLM_API_KEY=${DAY1_LLM_API_KEY} \
    LLM_BASE_URL=${DAY1_LLM_BASE_URL} \
    LLM_MODEL=${DAY1_LLM_MODEL}
RUN pip install --no-cache-dir "openai>=1.0,<2"
COPY arena /opt/agent/arena
WORKDIR /opt/agent
ENTRYPOINT ["python", "-m", "arena.main"]
```

构建：

```bash
DOCKER_BUILDKIT=0 docker build -t arena-test \
  --build-arg DAY1_LLM_API_KEY="$OPENROUTER_API_KEY" \
  --build-arg DAY1_LLM_BASE_URL="$OPENROUTER_BASE_URL" \
  --build-arg DAY1_LLM_MODEL="$OPENROUTER_MODEL" .
# 或
docker build --platform linux/amd64 --provenance=false -t arena-test \
  --build-arg DAY1_LLM_API_KEY="$OPENROUTER_API_KEY" \
  --build-arg DAY1_LLM_BASE_URL="$OPENROUTER_BASE_URL" \
  --build-arg DAY1_LLM_MODEL="$OPENROUTER_MODEL" .
```

本地运行需要额外资源时：

```bash
docker run -d --name arena-sim2 \
  --cap-drop=ALL \
  --security-opt no-new-privileges:true \
  --read-only \
  -v arena-sim2-work:/work \
  --tmpfs /tmp:rw,size=1g \
  --cpus 8 --memory 8g --pids-limit 1024 \
  --network bridge \
  --env-file "$PWD/.env.local" \
  -e ARENA_MODE=auto \
  -e INCLUDE_SOLVED=1 \
  -e SUBMIT_FLAGS=0 \
  -e MAX_CONCURRENT_CHALLENGES=6 \
  -e MAX_ATTEMPTS=1 \
  arena-test
```

正式提交：

```bash
DOCKER_CONFIG=/tmp/arena-docker-config \
  bash -c 'printf "%s" "$CTF_TOKEN" | docker login registry.in-cypher.com:5001 -u team-<id> --password-stdin'

docker tag arena-test:latest \
  registry.in-cypher.com:5001/team-<id>/agent:latest

DOCKER_CONFIG=/tmp/arena-docker-config \
  docker push registry.in-cypher.com:5001/team-<id>/agent:latest
```

## 11. 已知问题 / TODO

1. 旧 `src/`、`compose.yaml`、旧测试尚未删除。
2. `events.jsonl` 仍可能很大，未做轮转/压缩。
3. Bash 策略是启发式，不是完整 sandbox。
4. `already_solved` 无法证明本次 flag 正确，只是“题目已解”语义。
5. `SUBMIT_FLAGS=0` 用于模拟测试，不能用于正式提交。
6. 动态题并发上限为 1，是总时间瓶颈。
7. 未接入视觉多模态 `view_image`。
8. Docker 镜像中的 `arena/official` 是官方快照，正式镜像依赖 base image 覆盖 `/opt/agent`。
9. 当前官方 registry 上可能还是旧 digest，需要重新 push。
10. 本机 Docker 容器随本机关机停止；远端长跑应使用远端 Docker context 或独立主机。
